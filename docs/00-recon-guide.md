# Этап 0 — Разведка: что мне нужно от тебя из живой игры

Я не могу запустить Death Stranding. Всё, что ниже — пошаговые задания для тебя.
Результат каждого шага ты присылаешь мне текстом (адреса, байты, скриншоты не обязательны),
я встраиваю его в `data/offsets.json`, и следующий билд уже это использует.

Порядок важен: шаги 1–3 дают сетевую синхронизацию позиций (этап 1, пока в виде радара и
маркеров — это отладка, а не цель), шаги 4–5 — камера, шаг 6 — RTTI-дамп, который экономит
недели, шаги 7–9 — то, ради чего всё затевается: настоящий второй Сэм в твоём мире
(этап 2, `docs/stage2-puppets.md`).

## Инструменты

| Инструмент | Зачем | Где |
|---|---|---|
| Cheat Engine 7.5+ | поиск значений, pointer scan | cheatengine.org |
| x64dbg (snapshot) | перекрёстные ссылки, байты для сигнатур | x64dbg.com |
| ReClass.NET | просмотр структур по адресу | github.com/ReClassNET |
| CFF Explorer или PE-bear | импорты exe, timestamp | ntcore.com |
| Spy++ (в составе VS) или окно CE «Process list» | класс/заголовок окна | — |

**Безопасность.** Играй в оффлайн-режиме (игра спрашивает при старте; либо Steam offline).
DSLoader сам делает резервную копию сейвов в `dscoop/backups/` при первом запуске, но ещё
одну копию `%LOCALAPPDATA%\KojimaProductions\` сделай руками до первого сеанса с Cheat Engine.
Античита в DS DC нет; Denuvo (если он в твоей версии) не мешает чтению памяти, но может
ронять игру под классическим отладчиком — в CE выбери `Settings → Debugger → VEH Debugger`,
в x64dbg поставь плагин ScyllaHide (профиль «Basic»).

**Пиши адреса так:** `ds.exe+0x1A2B3C4` (модуль + смещение), а не абсолютные `0x7FF6...` — они
меняются при каждом запуске (ASLR).

## Шаг 1. Паспорт игры (10 минут, без запуска игры)

Пришли:

1. Магазин (Steam / Epic), версия из свойств exe, точное имя exe (`ds.exe`?), размер в байтах,
   SHA-256 (`certutil -hashfile ds.exe SHA256`).
2. Импортируемые DLL: CFF Explorer → *Import Directory* → список модулей. **Главный вопрос:
   есть ли там `version.dll`?** Если нет — пришли весь список, я переключу прокси на другую DLL
   (`dxgi.dll` / `winmm.dll`), это 15 минут работы.
3. `TimeDateStamp` из *File Header* (hex) — по нему мы различаем билды игры.
4. Папка игры и папка сейвов (`%LOCALAPPDATA%\KojimaProductions\...` — какое именно имя
   подпапки у DC-версии и есть ли внутри папка с числовым SteamID).
5. Запусти игру, дойди до главного меню, пришли заголовок и класс окна (CE → Process list →
   правый клик → *Window info*, или Spy++).

Дополнительно, если установишь текущий билд мода (`scripts/install.ps1`) и запустишь игру:
пришли `dscoop/logs/dsloader.log` целиком — там будут `build_id`, секции PE, результат бэкапа
и сообщение «game window found». Если лог не появился — `version.dll` не подхватилась (см. п. 2).

## Шаг 2. Позиция Сэма (Cheat Engine, 20–40 минут)

Decima хранит мировые координаты как **три double** (X, Y, Z; Z — вверх), поэтому сначала
ищем double, и только если ничего не находится — float.

1. Загрузись в мир, встань на ровном месте. Открой CE, подключись к процессу.
2. *Value Type* = `Double`, *Scan Type* = `Unknown initial value` → **First Scan**.
3. Поднимись по склону/лестнице на 1–2 метра (Z растёт) → `Increased value` → **Next Scan**.
   Постой секунду → `Unchanged value`. Спустись → `Decreased value`. Повтори 4–6 раз.
4. Когда осталось < 50 адресов, добавь все в список и смотри, какие меняются синхронно
   при ходьбе. Настоящая позиция — три double подряд: `X`, `X+8`, `X+16`. Обычно в списке
   несколько копий (физика, рендер, камера): нам нужна та, что меняется **сразу** при движении,
   а не с задержкой кадра.
5. Проверка: поменяй Z на +1.5 — Сэм должен чуть «подпрыгнуть». Если изменилась только копия,
   а Сэм не сдвинулся — это не она (но и такая копия нам полезна для чтения, запиши).
6. **Pointer scan**: правый клик по адресу X → *Pointer scan for this address*,
   `Max level = 5`, `Max offset = 4095`, остальное по умолчанию. Сохрани `.PTR`.
   Перезапусти игру, загрузись снова, найди позицию заново (шаги 2–4), в окне pointer scan →
   *Rescan memory* → адрес новой позиции. Останутся стабильные цепочки.
7. Пришли 5–10 самых коротких цепочек с базой в `ds.exe`, например:
   `ds.exe+0x04A1F2B8 → 0x38 → 0x1C0 → 0x40` (CE показывает их как
   `"ds.exe"+04A1F2B8` и колонки Offset 0..N).

Если double ничего не даёт за 15 минут — повтори с `Float` (тогда тип в `offsets.json` будет
`vec3f`).

## Шаг 3. Из статической базы — в сигнатуру (x64dbg, 15 минут)

Статический адрес `ds.exe+0x04A1F2B8` сам по себе «протухнет» после патча. Нам нужны байты
кода, который к нему обращается.

1. Открой x64dbg, присоединись к игре (или запусти через него), `Ctrl+G` → `ds.exe+0x04A1F2B8`
   (в окне дампа).
2. Правый клик по адресу в дампе → *Find references to → Address* (или поставь hardware
   breakpoint on access и пройдись в игре).
3. В списке ссылок выбери инструкцию вида `mov rax, qword ptr ds:[rip+...]`,
   `mov rcx, qword ptr ds:[...]` или `lea rax, [...]`, желательно в небольшой функции.
4. Выдели её и 3–4 инструкции вокруг → правый клик → *Copy → Selection* и пришли мне текст.
   Он выглядит так:
   ```
   00007FF6A1B2C3D4 | 48:8B05 ADDE1200   | mov rax,qword ptr ds:[7FF6A1C5A288]
   00007FF6A1B2C3DB | 48:85C0            | test rax,rax
   00007FF6A1B2C3DE | 74 1A              | je ds.7FF6A1B2C3FA
   00007FF6A1B2C3E0 | 48:8B88 C0010000   | mov rcx,qword ptr ds:[rax+1C0]
   ```
   Я сам превращу это в паттерн `48 8B 05 ?? ?? ?? ?? 48 85 C0 74 ?? 48 8B 88` и посчитаю
   `rip.disp/len`. Если хочешь проверить уникальность сам: `Ctrl+B` в x64dbg → паттерн →
   должен быть ровно 1 результат.

Шпаргалка по RIP-relative инструкциям (для `offsets.json` → `rip`):

| Байты | Инструкция | disp | len |
|---|---|---|---|
| `48 8B 05 xx xx xx xx` | mov rax,[rip+x] | 3 | 7 |
| `48 8B 0D xx xx xx xx` | mov rcx,[rip+x] | 3 | 7 |
| `48 8D 05 xx xx xx xx` | lea rax,[rip+x] | 3 | 7 |
| `E8 xx xx xx xx` | call rel32 | 1 | 5 |
| `48 89 05 xx xx xx xx` | mov [rip+x],rax | 3 | 7 |
| `F2 0F 10 05 xx xx xx xx` | movsd xmm0,[rip+x] | 4 | 8 |

## Шаг 4. Поворот Сэма (CE, 15 минут)

В Decima `WorldTransform` = матрица 3×3 из float (9 чисел в диапазоне −1…1, 36 байт, обычно
дополнены до 48) и **сразу за ней** три double позиции. Поэтому:

1. Открой адрес позиции X в *Memory View*, отступи назад 0x30 байт, включи отображение как
   *Float*. Если видишь девять чисел в [−1, 1], три из которых меняются при повороте Сэма
   на месте (мышью/правым стиком) — это она. Пришли смещение относительно X (ожидаемо `−0x30`)
   и девять значений при взгляде «на север» и при взгляде «на восток», чтобы я понял, какая
   строка — forward.
2. Если матрицы нет, ищи кватернион (4 float, сумма квадратов = 1) или одиночный угол
   (float, −3.14…3.14 или 0…360), меняющийся при повороте: *Unknown initial* → *Changed* при
   повороте → *Unchanged* стоя.

## Шаг 5. Камера (CE, 20 минут) — для маркеров над головой

Без этого шага мод работает, но игроков видно только на радаре в углу.

1. Повтори шаг 2, но двигай **камеру** вокруг стоящего Сэма (позиция Сэма не меняется,
   позиция камеры — да). Найди три double камеры и, как в шаге 4, матрицу 3×3 перед ними.
2. FOV: в настройках/фоторежиме подвигай ползунок поля зрения и найди float, равный значению
   ползунка (в градусах), либо `tan(fov/2)`. Если ползунка нет — пропусти, я возьму 55°.
3. Pointer scan для позиции камеры (как в шаге 2.6) и ссылка на базу (как в шаге 3).

Альтернатива для продвинутых: найти готовую матрицу view*projection (16 float) — она обычно
лежит в константном буфере рендера и её труднее достать стабильно, поэтому идём через
трансформ камеры.

## Шаг 6. Проверка раскладки RTTI (x64dbg или CE, 20 минут)

У Decima своя рефлексия: для каждого класса в `.data` лежит запись с именем, размером,
таблицей полей и базовых классов. Наш дампер (`dsloader.json → "dump_rtti": true`) умеет
сканировать `.data` по раскладке из `offsets.json → rtti.layout`, но по умолчанию там
раскладка Horizon Zero Dawn PC, которую надо подтвердить.

1. В x64dbg: *Memory map* → секция `.rdata` → правый клик → *Find Pattern* → ASCII
   `RTTIRefObject` (или `Entity`, `WorldPosition`). Запомни адрес строки `S`.
2. *Find references* к `S` (поиск 8-байтного указателя на `S` в `.data`: *Memory map → .data
   → Find Pattern*, тип `Hex`, байты адреса `S` little-endian). Получишь адрес `P`, где лежит
   указатель на имя.
3. Начало записи RTTI = `P − nameOffset`. По умолчанию `nameOffset = 0x38`, т.е. запись
   начинается на `P − 0x38`. Пришли **0x100 байт** с адреса `P − 0x60` (с запасом) в hex —
   *Binary → Copy* из дампа. Я по ним подтвержу/исправлю `kindOffset`, `sizeOffset`,
   `memberTableOffset` и т.д.
4. Быстрая проверка без ручной работы: поставь в `dsloader.json`
   `"dump_rtti": true, "rtti_force_unverified": true`, запусти игру, подожди 10–20 секунд
   после меню и пришли из `dsloader.log` строки `rtti: ...`. Если найдено несколько тысяч
   классов с нормальными именами (`Entity`, `Mover`, `PlayerCharacter`…) — раскладка верна,
   пришли файл `dscoop/dumps/rtti_<build>.json` (он может весить 10–50 МБ — заархивируй).
   Если 0 или мусор — идём по пунктам 1–3.

## Шаг 7. Игровой тик (x64dbg, 20 минут) — этап 2, марионетки

Все вызовы движка (спавн, перемещение второго Сэма) должны идти из игрового потока.
Нужна функция, которая вызывается ровно один раз за кадр.

1. На адрес позиции Сэма (X из шага 2) поставь **hardware breakpoint on write** (x64dbg:
   правый клик в дампе → Breakpoint → Hardware, Write, 8).
2. Сделай шаг в игре — сработает запись. Посмотри *Call stack* (`Alt+K`): пришли 8–10 верхних
   кадров (адреса как `ds.exe+...` и имена, если есть).
3. Поднимись по стеку до функции, которая вызывается раз в кадр (обычно 3–5 уровней вверх:
   «update мира» → «update сущностей» → «mover»). Проверить легко: breakpoint на её начало,
   счётчик срабатываний (`Breakpoint → Edit → Log`/`hit count`) за 1 с ≈ FPS.
4. Пришли байты начала этой функции (первые 24–32 байта, *Copy → Selection*) и её аргументы по
   прологу (сколько регистров сохраняет, есть ли `movss xmm1` = dt).

## Шаг 8. Перемещение и спавн сущности (x64dbg + RTTI-дамп, 1–2 часа)

1. **Entity_SetWorldTransform**: функция из шага 7.2, которая непосредственно пишет позицию
   (нижний кадр стека, где `movsd [rcx+..], xmm0` или `movups`). Пришли её начало и
   посмотри, что в `rcx` (Entity? Mover? WorldTransform?) — первые 0x40 байт по `rcx` в hex.
2. **Ресурс Сэма**: в RTTI-дампе (шаг 6) найди класс игрока (`Player*`, `HumanoidEntity`,
   `PlayerCharacter`) и поле типа `EntityResource`/`Ref<...Resource>` — пришли имя класса,
   поле и его offset. Если дампа ещё нет: в ReClass открой адрес `local_player`, ищи указатель
   на структуру, у которой по `+0x8..+0x40` есть указатель на строку вида
   `entities/characters/sam/...` (пути ресурсов Decima читаемые).
3. **Entity_SpawnFromResource**: поставь breakpoint на функцию чтения ресурса/создания
   сущности в момент, когда в мире появляется NPC (подойди к лагерю МУЛов издалека или
   вызови спавн портера-NPC). В стеке ищи функцию с двумя указателями-аргументами: ресурс
   и трансформ. Альтернатива: xref на строку `"EntityResource"` → RTTI класса → его
   `m_Constructor`/фабрика. Пришли кандидатов (начало функции + аргументы).
4. **Entity_Destroy** (необязательно): парная функция удаления — часто рядом в коде.

## Шаг 9. Анимация (CE, 30 минут) — чтобы марионетка шла, а не скользила

1. *Unknown initial value* (4 байта) → переключай состояние Сэма: стоит/идёт/бежит/присел →
   `Changed`/`Unchanged`. Нужен int/enum, который принимает разные стабильные значения в
   каждом состоянии. Пришли адрес (pointer scan, как в шаге 2) и таблицу «состояние → значение».
2. Параметры скорости: float 0…~7 (м/с) рядом с матрицей трансформа, растущий при беге.
3. Если найдёшь функцию, которая эти значения пишет (hardware bp on write) — её начало
   пришли как `Mover_SetLocomotion`.

## Что присылать (шаблон)

```
Шаг 1: Steam, ds.exe 1.xx, size=..., sha256=..., TimeDateStamp=0x...., imports: version.dll да/нет, ...
       окно: class="...", title="..."
Шаг 2: pos X = ds.exe+0x........ → 0x.. → 0x.. (double), копии: ...
Шаг 3: (вставь текст из x64dbg Copy→Selection)
Шаг 4: матрица на X-0x30: север = [..9 чисел..], восток = [..9 чисел..]
Шаг 5: cam pos = ..., cam rot = ..., fov = ...
Шаг 6: hex 0x100 байт с P-0x60: ...   или строки rtti: из лога
Шаг 7: call stack при записи позиции: ...; Game_Tick = ds.exe+..., байты: ...
Шаг 8: SetWorldTransform = ds.exe+..., rcx→...; ресурс Сэма: класс/поле/offset; Spawn = ...
Шаг 9: anim state: ds.exe+... стоит=.. идёт=.. бежит=.. присед=..
Проблемы/наблюдения: ...
```

Логи `dscoop/logs/*.log` и `dscoop/reports/report_*/` (кнопка «Собрать отчёт» в меню F9)
прикладывай всегда — там версия игры, разрешённые сигнатуры и ошибки.
